ゲームのプログラミング解説：常連シャドウイング

1. 全体構成
このゲームは HTML、CSS、JavaScript の3層で作られています。
HTML は画面の骨組み、CSS は見た目、JavaScript はゲームのルールと動きを担当しています。

構成の中心は次の3つです。
・index.html: 画面に出す要素を配置する
・style.css: 背景、キャラクター、演出、レスポンシブ対応を担当する
・game.js: ゲーム本体の状態管理、入力処理、敵の行動、フェーズ切り替えを担当する

2. ゲームの基本アイデア
このゲームは「尾行フェーズ」と「入店フェーズ」の2段階で進みます。
プレイヤーは Z で前進、X でごまかしを行い、常連客の背後を保ちながら店までついていきます。
店に近づくとダッシュ演出へ移り、最後にタイミング入力で成功か失敗かを判定します。

3. 状態管理
game.js では state という1つのオブジェクトに、ゲームの現在状態をまとめています。
たとえば次のような値を持っています。
・phase: いまのフェーズ（tailing, dash, pose, result など）
・playerX / patronX: 主人公と常連の横位置
・stamina: ごまかしゲージ
・distanceToShop: 店までの距離
・patronBehavior: 常連の現在行動
・stageLevel: 周回ごとの難易度レベル
・cornerTransitionTimer: 画面切り替え中かどうか

この作りにしているので、画面のどこで何が起きているかを1か所で管理できます。

4. 入力処理
入力は Z と X を基本にしています。
JavaScript では keydown と keyup で押下状態を保持し、長押しが必要な仕様を実現しています。
スマホ用にはボタンを用意していて、pointerdown と pointerup で同じ処理を呼びます。

入力は input オブジェクトに保存されます。
・advanceHeld: Z が押されているか
・poseHeld: X が押されているか
・advancePresses: ダッシュ中の連打回数
・posePressedThisFrame: キメ顔判定用の1フレーム入力

5. 尾行フェーズ
尾行フェーズでは、常連の行動をランダムで切り替えています。
主な行動は次の通りです。
・walk: 普通に歩く
・stop: 立ち止まる
・lookbackCue: 振り返る前の予告
・lookback: 実際に振り返る
・doublelookCue: 二度見の予告
・doublelook: 二度見の本体
・feint: フェイント

常連の行動は chooseBehavior() で決めています。
ここでは難易度に応じて各行動の出やすさを変えています。

6. 予告の「？」
プレイヤーが反応しやすいように、常連が振り返る少し前に「？」を出しています。
これは patronAlert という要素を使って実現しています。

流れは次の通りです。
1. chooseBehavior() で lookbackCue または doublelookCue を選ぶ
2. その間は ? を表示する
3. 予告時間が終わると本当の振り返り状態に入る

これにより、いきなり失敗するのではなく、少しだけ準備時間を作っています。

7. ごまかしゲージ
ごまかし中は stamina が減少し、何もしていない時は回復します。
X を押し続けるとごまかし状態になりますが、押しっぱなしにし続けるとゲージが尽きて失敗します。

この仕組みによって、ただ X を押しているだけでは勝てず、必要な場面だけごまかす判断が必要になります。

8. 距離管理
distanceToShop は店までの残り距離として使っています。
画面上の距離バーはこの値をもとに更新されます。
常連が右端へ進むと、店に着く前は wrapStageLoop() で左側へ戻して、ステージが続いているように見せています。

このとき、ただ座標を戻すだけでなく、現在の通りが変わる演出として暗転を入れています。

9. 画面切り替え演出
周回時は startCornerTransition() が呼ばれます。
この処理では次のことをしています。
・cornerTransitionTimer をセットして暗転中にする
・stageLevel を1つ上げる
・操作を止める
・「角を曲がった」と大きく表示する
・演出終了後に通常プレイへ戻す

この演出によって、ただループしているのではなく、場所が変わった感じを出しています。

10. 難易度調整
難易度は getDifficultyProfile() でまとめて計算しています。
周回数 stageLevel に応じて、以下が少しずつ厳しくなります。
・常連の歩く速さ
・振り返りや二度見の発生率
・ごまかし予告の長さ
・ごまかしゲージの減りやすさ
・回復の速さ

逆に序盤はこれらをかなりゆるめています。
そのため、最初の区画では遊びやすく、周回するほど緊張感が増します。

11. 入店フェーズ
店に着くと dash フェーズへ移ります。
ここでは A を連打してダッシュし、dashMeter を100まで上げると次の pose フェーズへ進みます。

dashMeter は連打数で増え、時間経過で少しずつ減ります。
つまり、速く押し続けるほど有利です。

12. キメ顔フェーズ
pose フェーズでは、画面中央のタイミングバーで X を押すと成功します。
timingCursor が行ったり来たりし、その中の sweet spot に入った瞬間だけ成功判定になります。

このフェーズは完全にタイミングゲームとして作られています。

13. 描画の更新
render() では state の値を見て、HTML 要素の位置やクラス名を更新しています。
つまり、ゲームのロジックと見た目を分けています。

この分離のおかげで、
・ロジックが変わっても描画を壊しにくい
・演出やUIだけを CSS 側で調整しやすい
という利点があります。

14. まとめ
このゲームは、状態管理、入力の保持、フェーズ分岐、難易度プロファイル、演出用オーバーレイを組み合わせて作られています。
見た目はシンプルですが、内部では「尾行」「周回」「暗転演出」「ダッシュ」「タイミング判定」が順番につながるように設計されています。

要するに、1つの画面で終わるゲームではなく、状態が次々に切り替わる小さなゲームループです。
